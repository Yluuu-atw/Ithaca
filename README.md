# Journey 🧭 情侣旅行规划 + 记账

一个**数据与呈现分离**的跨端响应式网站，两个人一起规划旅行、记账、打包、收藏心愿。

- 清新优雅的交互界面，自动适配 **电脑 / 平板 / 手机**
- **多设备实时同步**：两人各开一个浏览器，一方改动，另一方即时看到
- 数据存成 **JSON 文件**，可随时导出备份 / 导入恢复
- 零依赖，仅用 Node 内置模块，无需 `npm install`

## 功能

| 模块 | 说明 |
| --- | --- |
| 🧳 旅行 | **多趟旅行并存**，每趟有独立的行程/账目/收藏/照片，互不干扰；可切换、新建、归档、删除 |
| 🏠 概览 | 行程信息（名称/目的地/日期/币种/成员）、总花费、清单进度、花费分类占比、结算 |
| 🗺️ 行程 | 按天排行程：时间、地点、分类、预估花费、备注；支持**简洁/详细模式**切换，简洁模式点卡片看详情 |
| 📌 攻略 | 收藏要订的酒店/餐厅/景点等：**分类筛选 + 实时搜索 + 卡片 + 详情弹窗**（状态：想去/待订/已订） |
| 🎫 票据 | 预订凭证：**机票/火车票/大巴票/酒店**，统一记录起终点、日期时间、承运、座位/房型、订单号、金额、付款人；票种+状态双筛选 |
| 💰 记账 | 记支出：金额、分类、谁付的、均摊/单方，自动算「谁该补谁」 |
| 🎒 清单 | 打包清单：分类、谁带、勾选进度 |
| ⭐ 心愿单 | 想去的地方/想做的事，优先级 + 状态（想去→排入行程→已完成） |
| 📍 地图 | 行程点按天着色标注在地图上，支持 GPX 足迹导入 |
| 📷 照片 | 旅行照片手帐墙，按天分组 |

## 快速开始

```bash
cd Journey
npm start        # 或 node server.js
```

然后浏览器打开：

- 本机：<http://localhost:3000>
- 手机/另一台设备（同一 Wi-Fi）：`http://<你的电脑局域网IP>:3000`

启动时终端会打印局域网地址，例如 `http://192.168.1.3:3000`，直接发给 TA 即可。

> 换端口：`PORT=8080 npm start`

## 数据与呈现分离（架构）

```
Journey/
├── server.js            # 后端：静态服务 + REST + SSE 实时 + JSON 原子持久化
├── data/
│   ├── schema.js        # ★ 数据模型唯一真相源（结构/分类/默认值/归一化）
│   └── db.json          # 运行时数据（自动生成，私有数据）
└── public/              # 前端（呈现层）
    ├── index.html       # 页面骨架
    ├── css/style.css    # 样式（响应式）
    └── js/
        ├── store.js     # ★ 数据层：API 通信 + 乐观并发 + SSE 订阅
        ├── render.js    # 视图层：纯渲染，把数据画成 HTML
        └── app.js       # 交互层：事件委托 + 弹窗 + 导入导出
```

**关键设计**：界面不直接读写数据。`app.js` 只调用 `Store.mutate(fn)` 描述「改了什么」，
`store.js` 负责保存与同步，`render.js` 负责重新绘制。因此：

- 以后想改数据结构，只需动 `data/schema.js` + `store.js` 里的常量，界面自动跟随
- 想换样式/加页面，只动 `render.js` + `style.css`，数据层不动

**多旅行**：`db.json` 顶层只有 `meta`（版本号，管乐观并发）和 `trips[]`，每趟旅行是一个
自带全部模块的独立空间。`Store.getState()` 返回的是**当前旅行**，形状与单旅行版完全一致，
所以 `render.js` / `app.js` 读 `s.meta`、写 `d.expenses` 的代码一行都不用改。
旧的单旅行数据会被 `normalize()` 自动包成 `trips[0]`，一条不丢。当前看哪趟旅行记在
每台设备的 `localStorage` 里，两人可以同时看不同的旅行。

## 数据备份 / 迁移

- **导出**：页面右上角「导出」，下载一个 `journey-日期.json` 文件
- **导入**：右上角「导入」，选择之前导出的 JSON 文件（会覆盖当前数据，请先备份）
- 数据文件本体在 `data/db.json`，直接拷贝它也是一种备份

## 常用操作

1. 先在 **概览** 页填好行程名称、目的地、日期、币种、成员姓名
2. 去 **行程** 页「新建一天」，再点某天的「＋ 安排」排行程
3. 去 **记账** 页「记一笔」，选谁付的 + 均摊/单方，自动算账
4. 去 **清单** 页把要带的东西加进去，出发前勾选
5. 去 **心愿单** 记下想去的地方，排进行程后改状态

## 扩展指引（给未来的自己/书记）

- **加一个分类**：改 `data/schema.js` 的 `CATEGORIES` 和 `public/js/store.js` 的 `CONST`，即可
- **加一个字段**：在 `schema.js` 的注释里补字段定义 → `render.js` 对应渲染 → `app.js` 表单收集
- **加一个页面**：`render.js` 的 `TABS` 加一项 + 写 `renderXxx()` → `app.js` 加对应 action

## 说明

- 数据存储是「整份文档 + 版本号」的乐观并发：两人几乎同时改时，后写入方会自动拉取最新并重放自己的修改，不会静默丢数据
- 实时同步走 SSE（`/api/events`），断线自动重连
- 所有数据存在 `data/db.json`，已被 `.gitignore` 忽略，不会误提交到版本库
