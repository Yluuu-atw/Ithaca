# 九州 ITHACA · 旅行规划与记账

数据与呈现分离的跨端响应式旅行网站，支持多人协作规划、记账、打包和收藏。

- 清新优雅的交互界面，自动适配 **电脑 / 平板 / 手机**
- **多设备实时同步**：同一旅行的协作者即时看到改动
- 用户名密码和通行密钥登录；用户名用于登录，昵称可在账号中单独编辑；正式成员可创建自己的旅行
- 旅行成员关联正式账号或仅限当前旅行的临时身份；支持替换成员并转移原有记录
- 成员可为每趟旅行设置独立昵称、头像和颜色；已占用的头像与颜色不会出现在同旅行其他成员的选项中
- 临时成员凭专属链接免登录访问，只能编辑自己添加的内容；正式编辑成员可修改临时成员内容
- 邀请正式成员加入旅行，或生成可撤销的匿名只读链接
- 数据存成 **JSON 文件**；浏览器可导出或导入旅行
- 个人背景主题在首页和所有旅行页面生效，品牌标志随主题调整，支持深色配色
- 首页可直接继续上次访问的旅行，或从最近旅行直接记一笔；手机端针对无旅行、单旅行和多旅行显示对应入口
- 手机端顶栏可切换旅行；成员身份在「概览」成员卡管理，背景与分享在「概览」，导入和导出在「管理旅行」
- 服务端使用 Node.js 22 及 WebAuthn 验证依赖
- 图标使用 [Fluent Emoji](https://github.com/microsoft/fluentui-emoji)（MIT）的 3D 样式，已内置在 `public/vendor/fluent-emoji/`

## 功能

| 模块 | 说明 |
| --- | --- |
| 旅行 | 多趟旅行并存，每趟有独立的行程、账目、收藏和照片；可切换、新建、归档、删除 |
| 概览 | 行程信息、可手动编辑的途经地点（留空取自行程）、总花费、清单进度、花费分类占比、结算 |
| 行程 | 按天排行程，支持跨天记录、拖动排序和简洁/详细模式切换 |
| 攻略 | 收藏酒店、餐厅、景点等，支持分类筛选、搜索和详情 |
| 票据 | 是记账页的筛选视图，筛出附有截图或票据信息的账目；可查看票种、预订状态、路线和原图 |
| 记账 | 可从截图填写支出并定位地点；账单列表点开后先查看只读详情，再选择编辑或删除；新账目静默使用当地当前时间；按旅行天数汇总每日金额；按当前成员显示应转、应收及个人转账标记 |
| 清单 | 按旅行类型推荐物品，支持模板、分类和勾选进度 |
| 心愿单 | 记录地点和事项的优先级及状态 |
| 地图 | 按天标注行程点，支持 GPX 足迹导入 |
| 照片 | 按天分组；照片墙与封面使用私有 WebP 缩略图，点击查看原图并支持缩放、切换和下载 |

## 快速开始

```bash
cd Ithaca
npm ci
npm start
```

然后浏览器打开：

- 本机：<http://localhost:3000>
- 手机/另一台设备（同一 Wi-Fi）：`http://<你的电脑局域网IP>:3000`

首次打开页面时注册账号，再创建自己的旅行。每趟旅行的成员与权限由所有者管理。

通行密钥在「账号」中添加。登录时先输入用户名；已有通行密钥的账号会直接请求设备验证，失败后可改用密码。密码输入后按回车即可登录。设备可提供 Apple 密码、Face ID、Touch ID、指纹或跨设备扫码；验证方式取决于浏览器和设备。公网使用时需配置 HTTPS 与准确的 `ITHACA_ORIGIN`，例如 `https://ithaca.example.com`。登录默认保持 30 天，可用 `ITHACA_SESSION_DAYS=1` 至 `90` 调整；会记住上次登录的用户名，不保存密码。

在「记账」页顶部或账目表单中点击「让我看看」选择截图，页面会填写能识别的字段，保存前可以核对修改。识别、上传和保存的进度固定显示在弹窗底部；识别或上传期间可主动取消，未保存的内容会保留在表单中。识别只使用已有的票种和支出分类；付款人及分摊成员由用户选择。支出截图里的明确店名与地址会尝试匹配地点；存在歧义时由用户选择，找不到时留空。也可手动搜索地点、在地图上选点或使用设备 GPS；照片含 GPS 时仅作为建议。地点查询使用 OpenStreetMap Nominatim 的公共地点数据并遵守其使用限制。图片随记录保存，显示时使用私有 WebP 预览，点击可查看、缩放和下载原图。服务端配置 `ARK_API_KEY` 后启用识别，可用 `ARK_MODEL_ID` 指定模型；未配置时入口改为「添加图片」，仍可保存截图并手动填写。

> 换端口：`PORT=8080 ITHACA_ORIGIN=http://localhost:8080 npm start`

## 数据与呈现分离（架构）

```
Ithaca/
├── server.js            # 后端：静态服务 + REST + SSE 实时 + 访问控制
├── data/
│   ├── schema.js        # ★ 数据模型唯一真相源（结构/分类/默认值/归一化）
│   ├── people.js        # 旅行成员身份、作者归属和成员替换引用
│   ├── document-policy.js # 按身份校验整份文档写入
│   ├── settlement.js    # 按分计算成员结算和个人转账计划
│   ├── place-search.js  # 公共地点查询、限速和缓存
│   ├── sharing.js       # 正式/临时成员、邀请和分享链接
│   ├── db.json          # 旅行数据（自动生成，私有数据）
│   ├── auth.json        # 账号、密码摘要、通行密钥公钥和会话（私有数据）
│   ├── uploads/         # 原图（私有数据）
│   └── thumbs/          # 按需生成的 WebP 缩略图缓存
└── public/              # 前端（呈现层）
    ├── index.html       # 页面骨架
    ├── css/style.css    # 样式（响应式）
    └── js/
        ├── store.js     # ★ 数据层：API 通信 + 乐观并发 + SSE 订阅
        ├── render.js    # 视图层：纯渲染，把数据画成 HTML
        └── app.js       # 交互层：事件委托 + 弹窗 + 导入导出
```

**关键设计**：界面不直接读写数据。`app.js` 只调用 `Store.mutate(fn)` 描述「改了什么」，
`store.js` 负责保存与同步，`render.js` 负责重新绘制。因此：

- 以后想改数据结构，只需动 `data/schema.js` + `store.js` 里的常量，界面自动跟随
- 想换样式/加页面，只动 `render.js` + `style.css`，数据层不动

**多旅行**：`db.json` 顶层包含版本号、旅行、权限、附件归属和用户私有资料。服务端按账号或分享链接过滤返回的旅行。当前旅行只记录在本设备的 `localStorage`。

**权限**：每趟旅行有一个所有者。正式成员拥有站内账号，可以创建旅行；所有者可把已注册账号加入旅行并赋予编辑或只读权限，也可创建仅在当前旅行有效的临时成员。临时成员使用专属链接免登录进入，能添加、编辑和删除自己写的内容；正式编辑成员可以修改临时成员的内容。所有者可替换成员，记录归属与付款人等引用会一起更新；同一旅行不允许重复身份。成员移除后，有内容归属的身份会保留为「待关联」，所有者可稍后替换。匿名分享链接只读，可单独撤销。浏览器的「导入」会新增当前正式账号拥有的旅行，不会覆盖原有旅行。

**成员资料**：在「概览 → 成员 → 编辑我的旅行资料」中设置本旅行昵称、头像和颜色。正式成员的旅行昵称默认跟随账号昵称，账号昵称默认是用户名；临时成员默认使用其身份名称。清空旅行昵称或点击「恢复跟随」可继续使用默认名称。只读正式成员和临时成员也能修改自己的旅行资料，匿名分享访客不能修改。昵称变化不会改动历史账目中的成员标识。

**记账与结算**：新账目的时间静默默认为设备当地当前日期和时间，编辑账目保留原时间；截图识别不会覆盖账目时间。地点和坐标与关联行程同步，标记后可在旅行地图上查看。每日支出按旅行第几天展示金额；成员列可横向滚动，首列与总支出列保持可见。「全部／票据」筛选同时作用于每日支出和账单；票据参考价不计入支出，只有账目的实际花费参与结算。记账页按当前正式或临时成员显示应转给谁、应向谁收款；「已转」「已收到」是各自保存的个人标记，不会发起付款，也不会改变其他成员的标记。「查看分摊明细」列出整趟旅行中自己参与的账目、精确分摊金额及占比和垫付金额；点击账目可查看原有详情。转账金额是整趟旅行互相垫付抵消后的净额。账目变动使转账金额变化时，相应标记恢复待确认。匿名只读分享只显示全员结算汇总。

## 账单图片凭证

在记账页点击「导出凭证」生成账单长图，可按票据筛选、附带图片。长图嵌入像素隐水印；超长内容分成连续编号的图片，生成时的账单快照保持不变。

扫描二维码或打开 `/verify-voucher`，选择 PNG、JPEG 或 WebP 图片核验。本站从隐水印读取凭证编号和页码，验证签名存档并逐块检查内容，支持一定范围的压缩和等比缩放，无需原始 PNG 文件。待核验图片仅在本站内存处理，不保存、不发送第三方；公开接口不提供原图和账单数据。

核验显示「未发现内容修改」「图片存在差异」或「无法核验」，水印可读不代表内容未经修改。过低分辨率、裁剪、旋转或严重压缩可能无法核验；多页凭证需核对全部页面。检测结果不构成任意编辑均可检出的保证，也不是实际付款证明。生成者或旅行所有者可撤销凭证。

## 数据备份与恢复

- **浏览器导出**：仅导出当前账号可访问的旅行和自己的私有资料，不包含照片文件或账号数据
- **浏览器导入**：将当前格式 JSON 中的旅行作为新旅行加入当前账号；原有旅行保留，旧格式文件会被拒绝
- **完整备份**：同时备份 `data/db.json`、`data/auth.json`、`data/uploads/`、`data/vouchers/` 和 `data/voucher-keys/`；恢复后重启服务
- **凭证与签名密钥**：`data/vouchers/` 保存不可变原图、预览和签名清单；`data/voucher-keys/` 保存长期签名私钥及公钥。私钥不能公开或加入 Git，不应在更新或重启时删除；已有凭证却缺失密钥时停止签发
- **缩略图缓存**：`data/thumbs/` 可删除并自动重新生成；每次读取仍按原图的访问权限校验

## 常用操作

1. 先在 **概览** 页填好行程名称、目的地、日期、币种，再从「成员」管理中添加已注册账号或临时成员；成员可单独编辑自己的旅行资料
2. 去 **行程** 页「新建一天」，再点某天的「＋ 安排」排行程；修改开始日期会将安排移到对应日期，关联账单的日期与时间同步更新
3. 去 **记账** 页「记一笔」，选付款人和分摊成员；在「我的结算」查看转账对象并标记自己的状态
4. 去 **清单** 页把要带的东西加进去，出发前勾选
5. 去 **心愿单** 记下想去的地方，排进行程后改状态

## 扩展指引（给未来的自己/书记）

- **加一个分类**：改 `data/schema.js` 的 `CATEGORIES` 和 `public/js/store.js` 的 `CONST`，即可
- **加一个字段**：在 `schema.js` 的注释里补字段定义 → `render.js` 对应渲染 → `app.js` 表单收集
- **加一个页面**：`render.js` 的 `TABS` 加一项 + 写 `renderXxx()` → `app.js` 加对应 action

## 说明

- 数据存储是「整份文档 + 版本号」的乐观并发：两人几乎同时改时，后写入方会自动拉取最新并重放自己的修改，不会静默丢数据
- 实时同步走 SSE（`/api/events`），断线自动重连
- 运行时数据位于 `data/`，已被 `.gitignore` 忽略
